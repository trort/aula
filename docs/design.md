# Design Document: Kids Learning Companion (Literacy & Math)

> 原始设计文档，2026-09 定稿入库。

## 1. Context & Motivation (我们为什么要做这个)

- 用户画像：4–6 岁幼小衔接儿童。
  - 处于汉字启蒙期，完全不会拼音，识字量少，依靠"字形图像与生活经验"直接对应语义。
  - 注意力周期极短（单次只能维持 3~5 分钟），对传统"做卷子/单调做题"极易产生排斥。
- 产品核心定位：线下教学的"数字伴侣"与"记忆检验器"，而不是完整的网课系统。
  - 学习新知识由家长在线下通过纸质教材、绘本和积木完成。
  - 该软件唯一的目标是自动化检验掌握度、抗遗忘巩固、以及捕捉薄弱混淆项。
- 交付目标：极度轻量、零维护成本、纯前端运行（GitHub Pages 托管的 PWA），无需用户注册或后端数据库，数据完全沉淀在孩子使用的本地设备中。

## 2. Core Design Philosophies (核心设计哲学)

### 2.1 零拼音与视觉直觉 (No Pinyin Dependency)

汉字对学龄前孩子来说是象形图像。设计中严格杜绝"字形 → 拼音 → 发音"的双重转换：

- 所有的交互仅建立在"纯正字形视觉"与"无歧义语音/图形语义"的直接映射上。
- 防作弊原则：孩子极擅长通过位置记忆、背景插画或声音前奏来"猜题"。因此所有视觉干扰项必须随机洗牌，且必须引入字形相似字（形近字）进行硬核辨析，剥离所有与汉字结构无关的线索。

### 2.2 闭环敏捷与低摩擦 (Low Friction, Short Sessions)

- 每次练习严格控制在 10 题左右（耗时 1~2 分钟），即测即走，杜绝冗长不可跳过的过场动画。
- 反应延迟（Latency）是核心数据指标：一眼认出（直觉）与纠结 5 秒（猜测）在记忆模型中具有完全不同的权重。

### 2.3 零资产负担原则 (Zero-Asset Architecture)

不依赖庞大的外部静态媒体库（音频包、重型插画）。优先使用浏览器现代标准 API（如 Web Speech 合成声音、CSS/SVG 纯代码渲染布局），保证项目克隆即跑、构建体积在几百 KB 内。

## 3. System Mental Model & Architecture (系统概念模型)

系统由两个独立的业务域（语文、数学）共享统一的会话循环（Session Loop）与本地持久化基座：

```
                    [ Unified App Shell (PWA) ]
                                 │
             ┌───────────────────┴───────────────────┐
             ▼                                       ▼
     [ Literacy Domain ]                     [ Math Domain ]
  - 核心驱动: 静态字库 + SRS 调度        - 核心驱动: 纯规则约束生成器
  - 目标: 记忆保持度与形近辨析            - 目标: 数感梯度与逆向代数思维
             │                                       │
             └───────────────────┬───────────────────┘
                                 ▼
                    [ Generic Game Mode Runner ]
                    - 统一的标准题目输入契约
                    - 统一的评测结果输出契约
                                 │
                                 ▼
                 [ Local Persistence & Telemetry ]
                 - localStorage 纯本地沙盒
                 - 防丢设计: 一键全量 JSON 导出/恢复
```

## 4. Domain Specs (业务领域设计意图)

### 4.1 Literacy Domain: 记忆衰减与动态插件模式

- 数据调度核心：
  - 每个汉字维护其独立熟练度分值、复习时间戳与混淆历史（例如"木"常被错认成"本"）。
  - 抽样算法本质是一个优先级队列（Priority Queue）：生疏字、刚错过的字权重极高；已掌握字权重极低，但随着未见天数增长权重动态爬升，促成定期巡检。
- 插件式 Mode 理念：
  - 底层只负责产出抽象的"测试任务（Task）"，具体的展现形式与逻辑高度解耦。
  - MVP 模式意图：
    - 听音辨字（Audio Choice）：标准提取器，测"音 → 形"唤起速度。
    - 找茬捉迷藏（Find Imposter）：纯视觉消歧，测孩子对微小笔画差异（如 大 vs 太）的敏感度。
  - 扩展性约束：未来接入"拖拽喂食"、"汉字积木拼装"等新玩法时，必须实现相同的标准生命周期（输入统一 Task，输出包含结果、耗时、错选项的统一 Result），不可侵入 SRS 算法本身。

### 4.2 Math Domain: 基于约束的规则推演

- 去题库化理念：算术练习不应存储静态 JSON，所有题目均为纯函数在给定边界约束下的即时演算。
- 认知梯度设计（L1 到 L6）：
  - 基础数感：10 以内加法（和为个位数）。
  - 进位启蒙：两个个位数相加，突破到两位数（凑十认知）。
  - 逆向操作：基础个位数减法。
  - 退位操作：两位数减一位数，结果是个位数（破十认知）。
  - 代数与逆向思维：不再只求等号右边的值，挖空移到等号左侧（如 ? + 3 = 7），让孩子理解算术的双向平衡关系。
  - 多位数扩展：双位数运算。
- 扩展性约束：生成器采用策略模式（Strategy Pattern），未来扩展乘法（L7）、除法（L8）只需追加规则策略，不影响练习界面的答题流程。

## 5. Non-Functional & Behavioral Requirements (非功能性意图)

- 设备与交互预期：
  - 目标载体以 iPad / 触屏平板为主。所有交互元素（字卡、数字键盘）必须遵循触控友好原则（大尺寸、清晰边距、明确的按下反馈状态）。
- 离线与去中心化：
  - 任何改动不得引入需要外部云端支持的依赖。断网状态下所有逻辑必须 100% 完整运行。
- 数据隐私与控制权：
  - 家长对所有学习轨迹拥有绝对控制权。系统必须提供人类可读的原始 JSON 导出与导入通道，方便更换设备时无缝迁移。
