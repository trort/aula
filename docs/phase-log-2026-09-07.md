# 学习岛（aula）· 阶段记录 v0.29（2026-09-07）

> 给"隔一段时间再接手"的人/模型看的项目快照。线上地址：https://trort.github.io/aula/

## 现在是什么

纯前端 PWA（Vite + React + TS + localStorage + Service Worker），GitHub Pages 自动部署（push main 即发布）。仓库：`trort/aula`，本地根目录即本仓库。App 内版本号显示在首页右下角（如 v0.29），与 `package.json` / `public/sw.js` 缓存名同步递增。

## 已实现（截至 v0.29）

- 双领域首页：识字岛 / 数学岛。
- **自动进阶引擎**（识字 & 数学共用 `src/lib/progress.ts`）：
  - 每字/每难度有连续掌握分 0–1（净答对 3 次=满分）；
  - 渐进混合：前一档约 50% 才开始混入下一档、90% 放量；旧内容保留复习权重；
  - 孩子不选字表/难度，只选 5/10/15 题。
- 识字四种玩法（首页可选，自动从当前课程选字）：
  1. 听音选字（卡片）；
  2. 找茬 3×3 —— **不计入识字掌握进度**（纯观察力，仍计本轮成绩/星星）；
  3. 传送带气球连句（≥4 字真实短语拼句，掌握 30 字后解锁；点对只消失那个气球、动物开心；点错气球保留、动物不开心、可重试；句尾按短语朗读）；
  4. 迷雾寻字（单幅随机暗幕 + Canvas 像素级刮开判定 + 拖进答案筐）。
- 数学：L1–L6 规则生成器；键盘填空作答；晓晓本地片段拼接语音（数字 0–99 + 加/减/等于/几）。
- 语音策略：单字/整词优先本地晓晓 mp3；缺失才回退系统 TTS；多音字在句子里按**短语音频**朗读（如"高兴"里的 兴）。
- 奖励：星星罐、动物贴纸簿、完美徽章、连击🔥、粒子与 WebAudio 音效；三种记录模式共享同一套逐字进度。
- 家长数据页：建议复习、逐字记录、字表进度、各难度掌握、练习历史、JSON 导出/导入。

## 数据文件位置

- 字表（可增删）：`wordbank/grade1-shang-recognition.json`
- 字形近干扰/读音：`src/data/curated.ts`
- 句子短语库：`src/data/sentences.ts`（只允许使用字库内字）
- 字音：`public/audio/{字}.mp3`；整词音：`public/audio/units/{短语}.mp3`；数学片段：`public/audio/math/`
- 进阶规则：`src/lib/progress.ts`；题目/玩法构造：`src/lib/tasks.ts`

## 内容规则（v0.33 起，加字/加题前必看）

完整说明见 [content-rules.md](content-rules.md)，一句话版本：

1. **听音类玩法（听音选字 / 迷雾寻字 / 连句喂食）的选项里不能有与目标字同音的字**（不计声调）。
   2026-09-11 排查出的 10 组：站/占、坐/座、快/块（完全同音）+ 风/凤、花/华、又/友、白/百、跑/泡、跳/挑、爸/巴（仅声调）。
   手工干扰项保留（找茬模式还要用），听音类出题时由 `src/lib/decoys.ts` 自动跳过。
2. 干扰项：形状像第一，其次优先"同期学过 / 已学过"的字；
   优先级由 `src/lib/decoys.ts` 出题时自动执行（同单元 → 已学单元 → 更晚单元 → 只当过干扰字的字，层内随机），
   已有数据不重写（2026-09-11 决定：这是 minor detail，只约束以后新增的内容）。
3. 读音表放在 `src/data/pinyin.ts`（新增字必须补读音），改完跑 `npm run check:content`（`npm run build` 已内置）。

## 已知问题与下一步

1. **多音字要做"读音级条目"拆分（重要、未做完）**：
   - 现在只是用"短语音频"绕开了句子里的读错（高兴的兴、快乐的乐）；
   - 用户明确要求：多音字的不同读音应作为**两个独立学习条目**（兴-xìng vs 兴-xīng，乐-lè vs 乐-yuè），各自有掌握记录/音频/例句；
   - 需要动底层：条目 key 从"字"变成"字+读音"，迁移 localStorage 旧数据，卡片上仍显示同一个字。
2. 刮刮乐手感待真机验证：刮开阈值 55%、笔刷 36px、判定区域半径 66px，可能需要按设备调。
3. 气球连句的"点对后气球飞向小动物"目前是直接消失+情绪动画，还没有真正的飞行动画（下一轮可做）。
4. 数学"整句朗读"仍是词组拼接，连贯感有限；将来若要更自然需每题型整句音频（或升级数据模型）。
5. 字库扩充流程：用户发新字表 → 与现有全部字去重 → 只加新字 → **补 `src/data/pinyin.ts` 读音** → 配形近干扰（不与目标同音）→ 跑 `npm run check:content` → 生成晓晓字音 → 推上线。注意新字包自动排在课程末尾（更进阶）。
6. 延迟（Latency）数据尚未接入 SRS；SRS 目前是简单的"错字到期 + 间隔拉长"。
7. 多孩子档案、找茬进阶（3×3 → 更多/更难）、数学自动出题策略仍待做。

## 常规操作

```bash
npm run dev        # 本地开发
npm run build      # 类型检查 + 构建
git push origin main   # 自动部署到 GitHub Pages（工作流 .github/workflows/deploy.yml）
```

生成新字音/词音：

```bash
edge-tts --voice zh-CN-XiaoxiaoNeural --rate=-5% --text "天" --write-media public/audio/天.mp3
```
